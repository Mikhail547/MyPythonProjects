# Алгоритм Евклида (Поиск НОД и НОК)

**Главная идея:** Наибольший общий делитель (НОД) двух чисел не изменится, если из большего числа вычесть меньшее. Чтобы это работало эффективно, вычитание заменяют на **остаток от деления (`%`)**.
* Время работы: **O(log(min(A, B)))** — работает мгновенно даже для чисел с сотнями знаков.

---

## 🟢 1. Классическая реализация НОД (Через цикл while)
Самый частый вариант на олимпиадах. Мы берем остаток от деления большего числа на меньшее, пока одно из них не станет нулем.

```python
def gcd(a, b):
    while b > 0:
        a, b = b, a % b  # Магия Python: меняем переменные местами за один шаг
    return a
```

### Как это работает под капотом (Пример для чисел 30 и 18):
1. `a = 30, b = 18` -> `b > 0`, заходим в цикл. `30 % 18 = 12`. Новые значения: `a = 18, b = 12`.
2. `a = 18, b = 12` -> `18 % 12 = 6`. Новые значения: `a = 12, b = 6`.
3. `a = 12, b = 6`  -> `12 % 6 = 0`. Новые значения: `a = 6, b = 0`.
4. `b = 0` -> цикл завершен, возвращаем `a = 6`. (6 — это действительно НОД для 30 и 18!).

---

## 🟡 2. Поиск НОК (Наименьшего Общего Кратного)
НОК — это минимальное число, которое делится без остатка и на `A`, и на `B`. Оно намертво связано с НОД математической формулой

```python
def lcm(a, b):
    # Используем целочисленное деление // чтобы вернуть int, а не float
    return (a * b) // gcd(a, b) 
```

---

## 🔴 3. Олимпиадный лайфхак: Встроенный модуль `math`
На реальном контесте (Всесиб НГУ, НТО, Изумруд) **не нужно писать алгоритм Евклида руками**. В Python всё уже написано и оптимизировано на языке Си под капотом!

```python
import math

# Поиск НОД для двух чисел:
print(math.gcd(30, 18))  # Выведет: 6

# Поиск НОД сразу для КУЧИ чисел (доступно в Python 3.9+):
print(math.gcd(24, 60, 36))  # Выведет: 12

# Поиск НОК (доступно в Python 3.9+):
print(math.lcm(30, 18))  # Выведет: 90
```

---

### ⚠️ Типичные грабли на олимпиадах:
Если в задаче числа огромные (например, \(10^{18}\)), стандартная формула НОК `(a * b) // gcd(a, b)` может сначала перемножить два гигантских числа, из-за чего компьютер потратит чуть больше памяти. Чтобы этого избежать, безопаснее сначала разделить, а потом умножить:
```python
return (a // gcd(a, b)) * b
```
